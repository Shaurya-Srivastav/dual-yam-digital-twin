Two arms. One dry dispenser.
No cameras.

A MuJoCo digital twin of a two-arm (I2RT YAM) water-cup station. One arm brings a paper or plastic cup under the spout, the other lifts a 360° lever for a 7-second pour, and the cup is served into a coaster. Every skill works from what real motors report: joint position, velocity, torque and gripper width.

Dance mode

The browser plays a song and reports its clock; the server tracks the beats of the audio itself (tempo, beats, downbeats, loudness) and poses both arms from phase-locked moves: sway, pump, wave, circle, point and clap, sized by the song's energy. These clips are silent because the recordings are copyrighted; the dots show the tracked beat. Run the dashboard locally with your own files to hear it.

How it works

1 · Plant1 kHz MuJoCo, MIT-style law τ = kp(q*−q) + kd(q̇*−q̇) + gravity. Friction, mass, gains, base pose, sensor noise and delay are randomized per trial; power-up calibration fits the gravity feed-forward from position sag.
2 · SenseContact is the torque residual after the controller's own gravity and friction model, mapped to a Cartesian force with −pinv(Jᵀ). Guards use force steps, never a true contact flag.
3 · PlanStrict mink IK, min-jerk synchronized trajectories, Cartesian lines for the last centimetres, collision checks against the bench, the dispenser and the other arm.
4 · SkillsGenerators, one yield per 2 ms tick: side grasp, spout insertion, lever routine, coaster place, pecks, handle search, one-arm flip. Failures are loud.
5 · LevelsA dependency graph over two arm lanes. The tap arm moves to the lever while the cup is still being carried.
6 · RefereeOnly the referee reads true poses: upright, centred, 7.0 s pour with the cup under the outlet, dispenser still, no collisions, arms at rest.

Finding the lever without moving it

Research on contact-pause grasping and proprioceptive articulated-object estimation says: set the threshold above noise but below breakaway.

  • A fingertip circles the valve and stops at about 0.9 N; the swivel needs about 1.5 N to turn.
  • The handle yaw is solved from the known hand and handle shapes (oriented-box intersection), not a fixed offset.
  • The finger pushes it to about 45°, backs off and touches again to confirm; if it is lost it searches again.
  • The swivel turns a full 360°; tested from −170° to 175°.

Finding the cup without cameras

Touch-only localisation keeps a belief and updates it from contact and no-contact readings.

  • Pecks from above on a coarse grid until something stands up.
  • Every peck outcome rules out cup positions that would contradict it, using the arm and cup models: a set-membership fit, 3–6 mm error.
  • Not yet: choosing each next peck by expected information gain.

The one-arm flip

With the hand 60° off the arm's line and tilted 20° down, the wrist is aligned so joint 6 alone rolls about 180° with the hand fixed.

  • The cup is held by its base band with its axis perpendicular to the approach axis, so one wrist roll turns it over.
  • Found by an IK search over attitudes; pitching in place is not reachable.
  • The cup is then lowered until its base edge touches the mat and released.

Side grasp that does not push the cup

  • Slides in with open jaws and complies sideways to contact force so the funnel pads centre the hand.
  • On closing, the stall width gives the chord 2·√(r²−s²): how far off the cup's axis the hand is, so depth is servoed from touch alone.
  • Force caps per grip; no weld, no snap.

What is still open, and why

  • Stack contact in Levels 2 and 3. The remaining stack sits 11 cm from the line between the cup arm's base and the spout, so every carry to the spout brushes it. Making it a hard planning obstacle leaves no route. Moving the stack to the coaster spot needs the tap arm's base moved to the measured solution; I tried it and the lever lift then fails inverse kinematics, because the lever routine was tuned for the current base. Fix: re-tune the lever arc for the new base.
  • Randomized success below target. Top cup slips during the pull on some draws; some stack heights have no reachable side grasp; the held cup can bump the valve; the coaster dish is wide enough for the real 2 cm slack so it no longer centres the cup.
  • Level 5 speed and housing contacts. About 100–150 s of simulated time. The tilted hand's housing can touch the target cup while pecking.
  • Dimensions not measured on the real station: tap-arm base position, coaster dish radius, spigot geometry. The station photos were not used to calibrate this round.
  • No hardware run. SimYam implements the i2rt Robot protocol and the same driver can target get_yam_robot, but it is untested on the arms.

IK equivalence

For all 12 taught Level 1 poses, strict Cartesian IK from unrelated seeds reproduces the real hand pose: ≤ 0.4 mm and 0.01°, so the skills use Cartesian goals, not cloned joint angles.

Run the live dashboard

The interactive twin (30–50 fps view with a view cube, step timeline with scrub-back, telemetry charts, belief-vs-truth overlay, Monte Carlo panel and Dance Mode) needs a Python process running MuJoCo, which a static host cannot run.

git clone https://github.com/Shaurya-Srivastav/dual-yam-digital-twin
cd dual-yam-digital-twin
git clone https://github.com/i2rt-robotics/i2rt third_party/i2rt     # arm and gripper models
pip install -r requirements.txt                                     # Python 3.11; ffmpeg for Dance Mode
./run_sim.sh                                                        # http://127.0.0.1:8090
python -m sim_station.selftest                                      # all levels + real-data replay
